# Secure first-run web installer (development preview)

## No-SSH cPanel bootstrap (staging preview)

A private staging ZIP containing Composer's runtime dependencies is generated by [Stage Distribution CI](https://github.com/manbir6-ux/84pad-core/actions/workflows/stage-distribution.yml). This is a staging build and not a signed or production-approved release.

1. In cPanel, create a **new empty MySQL database and database user**, grant access to that database. Back up any pre-existing sites; do not reuse their database.
2. Upload/extract `84pad-core-staging.zip` to a dedicated application folder. Point the website document root **only** to its `public/` folder; the rest must remain outside public access. Ensure PHP 8.3 or 8.4 with PDO MySQL, mbstring and required extensions.
3. In cPanel File Manager, create the private folder `storage/app/private/` (if it does not already exist). Create a text file named `first-run-token` in that private folder with **at least 32 randomly generated characters**. Do not use your cPanel password, send the token in chat, or store it in public/.
4. Open `https://YOUR_DOMAIN/84pad-bootstrap.php` over HTTPS. The page only appears if there is no `.env` yet and the private token is configured. Submit the token, new empty database name/user/password and MySQL host.
5. Bootstrap checks the empty database, creates a new `APP_KEY` and `.env` using exclusive file creation, and redirects to `https://YOUR_DOMAIN/setup` for the first Owner account. It cannot overwrite an existing `.env`.
6. Create the Owner with a strong password. The Laravel installer runs prerequisite checks and non-destructive migrations. After successful install the setup screens lock and the private token seed is deleted where file permissions allow.
7. Log in at `/login`. Remove/disable `public/84pad-bootstrap.php` after successful setup as defence-in-depth (the script also returns 404 once `.env` exists).

**Security boundaries:** The bootstrap trusts direct HTTPS, not arbitrary `X-Forwarded-Proto` headers. Behind some reverse proxies, the server may need a properly configured HTTPS endpoint; do not disable the HTTPS guard. The form never displays database errors or credentials. CSRF, attempt counters and installation locks are applied. Creating the private token in cPanel is an explicit owner step; this is not an unattended one-click installer.

**Current verification:** standalone negative-path tests cover absent/short tokens, HTTP access, an existing `.env`, unsupported cPanel input, and host prerequisites. Disposable CI MySQL tests cover manual `.env`/key initialisation. A real cPanel/API/browser staging acceptance test is still required before public deployment. GitHub Actions staging ZIP does not establish production readiness.

This is a **preconfigured-host installer**, not yet a complete upload-and-click installer. Do not deploy to an untrusted/public production hostname until the deployment/security acceptance phase passes.

## Obtain the values used by the setup wizard

**Automatic cPanel provisioning (optional):**
1. Log in to **your hosting cPanel** and open **Security → Manage API Tokens → Create** ([official cPanel guide](https://docs.cpanel.net/cpanel/security/manage-api-tokens-in-cpanel/)). If the menu is missing, the hosting provider may have disabled API tokens; choose Manual MySQL instead.
2. Name the token `84pad-first-run`, select an appropriate short expiration, and copy it once. Do **not** supply a WHM root token or the cPanel password. The token runs with the cPanel account's effective privileges, so revoke it in cPanel after provisioning.
3. Your **cPanel username** is shown in account details. The **cPanel server hostname** is the DNS hostname from the cPanel login URL, without `https://` or `:2083` (for example `server.example.net`). This installer accepts a publicly resolvable hostname with a valid TLS certificate; it deliberately rejects private or loopback targets.
4. Enter the suffixes for a **new database** and **new database user**. The script adds the cPanel account prefix and generates only these resources; choose a new, strong database password. The password will be stored privately in the new `.env`. The cPanel API token is NOT stored.
5. If port 2083, API access, or database creation privileges are unavailable, use the manual path below. cPanel API provisioning does **not** grant full server, SSH, domain, SSL or file-manager access automatically.

**Manual MySQL (works without a cPanel token):**
1. Open **Databases → Database Wizard / MySQL Database Wizard / MySQL Databases** (name depends on host/cPanel version). Create a **dedicated empty database**; never select an existing website database.
2. Create a database user and grant the user the privileges needed for Laravel migrations on **that database only**. Avoid server-level root access.
3. Copy the **full, possibly account-prefixed** database name and username, your chosen password, host (often `localhost`), and port (often `3306`) into 84PAD. Other hosting panels can supply equivalent MySQL/MariaDB credentials.

**Owner proof and deployment prerequisite:**
Before anyone can use the public installer, create a random 32–256 character value in the **private** `storage/app/private/first-run-token` file. This must not be the cPanel token or DB password. Use HTTPS and point the document root only to `public/`. The first screen now checks PHP 8.3+, required extensions, Composer runtime availability, and writable private directories, and refuses POST if prerequisites are missing.

**After initialisation:** the browser opens `/setup` to create the first Owner. You will need the same private first-run token for that Owner step. Once installation completes, the setup route locks and its token seed is removed when permissions allow. Core continues working without cPanel; optional ongoing access is configured separately in **Owner → Core Settings**, where the credentials are encrypted and plugins require explicit grants.

## Host preparation (cPanel, local server or staging)

1. Upload the application and install Composer dependencies, serving **only** the Laravel `public/` directory.
2. Copy `.env.example` to the untracked `.env` on the host. Configure `DB_*`, `APP_KEY`, `APP_URL` and HTTPS. Run `php artisan key:generate` on a trusted development host, or provide a valid generated APP_KEY through secure host configuration.
3. Generate a cryptographically random secret **at least 32 characters** and set `PAD_SETUP_TOKEN` in the untracked host environment. Never put this secret in Git, screenshots, browser URLs, emails, or CLI command arguments. When absent, GET/POST `/setup` both return 404.
4. Visit `https://your-domain.example/setup` and fill in the private token and Owner credentials. HTTPS and `APP_DEBUG=false` are required when APP_ENV=production.
5. The server checks prerequisites, applies **non-destructive Laravel migrations**, then uses a transaction and unique installation marker for the Owner.
6. Visit `/login` and log in with the new Owner account. Once installed, both setup routes are locked.

### Protections

- Setup secret is checked using `hash_equals`; incorrect secret returns a generic 403.
- Setup POST uses Laravel web/CSRF middleware and is rate limited.
- Absent setup secret, existing Owner or users, or an installed marker block setup.
- DB/host errors are returned as generic responses; passwords and tokens are not flashed back to users.
- Browser setup does **not** ask the user to reveal cPanel API keys or passwords to ChatGPT.
- Local plugins are separate and are not required during installation.

### Known limitations

- The staging ZIP includes Composer dependencies but is not a production-signed package. The standalone bootstrap can now generate `.env` / `APP_KEY` and optionally provision a database via cPanel. It still requires a private first-run token and compliant hosting. There is no automatic installation onto an arbitrary hosting account or any guarantee of API availability.
- Installation against an existing production database is not supported; use a dedicated empty DB and a full off-host backup.
- Concurrency is verified for the CLI installer with MySQL; browser session and real shared-host tests remain necessary.
- Successful automated CI does **not** mean this software has passed penetration testing or can be promoted to production.

Check `docs/PROGRESS.md` for the latest automated test results and outstanding acceptance steps.
